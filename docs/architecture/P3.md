## 1. 范围

P3 为已有的 8 个 naive 算子补齐多种 CPU 实现版本，并建立**显式选择 + bit-exact 对拍 + 可复现基准**的性能工程方法论。本文解释：

1. `CpuKernelLevel` 体系与"为什么显式选择"；
2. 各版本的职责边界与结果一致性约定；
3. AVX2 等指令集内核的编译隔离；
4. benchmark 的方法与解读纪律。

---

## 2. CpuKernelLevel：显式、编译期使能

`CpuKernelLevel`（[kernel_level.h](../../include/mycv/core/kernel_level.h#L11-L18)）定义了 CPU 实现的可选版本：

| 级别 | 含义 | 定位 |
| --- | --- | --- |
| `kNaive` | 可移植参考实现 | **ground truth**，所有对拍的基准 |
| `kOpenMP` | OpenMP 线程并行 | 多核吞吐 |
| `kTbb` | oneTBB 线程并行 | 多核吞吐（与 OpenMP 二选一或并存） |
| `kSimdGeneric` | 可移植 SIMD（编译器向量化/泛用 intrinsics） | 跨架构 |
| `kSimdAvx2` | x86-64 AVX2 | x86 性能 |
| `kSimdNeon` | aarch64 NEON | 未实现（声明保留） |

**关键规则**：

- 每个级别由独立的编译宏守卫（`MYCV_WITH_OPENMP` / `MYCV_ENABLE_TBB` / `MYCV_WITH_SIMD_GENERIC` / `MYCV_ARCH_AVX2` …）。**未编译的级别不会注册**，请求它返回 `kUnsupported`（[`P2.md`](./P2.md) §5）。
- `CpuBackend::SupportsKernelLevel` 由"编译期宏 + 已注册内核"共同决定，不虚报能力。
- **不做 CPU 特性探测、不做 auto-tuning**：调用方传 `kSimdAvx2`，就在跑 AVX2；没编进来就报错。科研要的是"我知道我在测什么"。

## 4. 结果一致性约定（bit-exact 纪律）

多版本不是"差不多就行"。P3 固定：

- **元素级算子**（Add / Mul / Cast / Normalize）：naive 与 OpenMP/TBB/SIMD/AVX2 之间 **bit-exact**（逐位相同）。
- **插值类**（Resize / WarpAffine）：允许 1e-5 相对误差，u8 输出允许 ±1。
- **跨后端**（CPU vs OpenCV vs CUDA）：1e-4 相对。

为什么元素级要求 bit-exact：SIMD/多线程只要保持"相同的运算顺序与舍入"就能逐位一致；一旦允许误差，就无法区分"实现 bug"与"浮点抖动"。对拍测试（`tests/consistency/test_cpu_kernels.cpp`）就是拿 naive 当 oracle，逐位比对其他版本。

## 5. 代码组织：公共骨架 + 级别只写内层

为避免 8 算子 × 6 版本的重复，公共循环骨架抽到 `src/ops/cpu_binary.h`、`cpu_cast.h`、`cpu_normalize.h`、`cpu_transpose.h` 等头文件。每个 `*_<level>.cpp` 只提供**内层循环**或并行分区，外层遍历、shape/stride 处理、输出分配由骨架统一完成。

以 `Add` 为例，目录结构：

```
src/ops/add/
├── add.cpp              # 公共校验 + 查表 + 分配 + 执行 + RegisterAddKernels
├── add_cpu_naive.cpp
├── add_cpu_omp.cpp
├── add_cpu_tbb.cpp
├── add_cpu_simd.cpp
└── add_cpu_avx2.cpp     # 单独编译单元，加 -mavx2
```

新增一个 CPU 级别 = 新增一个 `*_<level>.cpp` + 在 `Register*Kernels()` 加一行 `#ifdef` 注册，**不改 naive 与其他版本**（[`P0.md`](./P0.md) §7 扩展契约第 3 条）。

## 6. AVX2 编译隔离：独立 TU，不默认 `-march=native`

这是 P0 决策 D7 的落地：

- AVX2 内核放在**独立编译单元**（`add_cpu_avx2.cpp` 等），通过 CMake 的 `set_source_files_properties(... COMPILE_OPTIONS "-mavx2")` 单独加指令集选项。
- **库全局不使用 `-march=native`**。

> 动机：如果整个库都编 `-march=native`，分发到不支持本机指令集的机器上会触发非法指令（SIGILL）。把 AVX2 限制在少数 TU，并通过 `SupportsKernelLevel`/运行期请求显式暴露，跨平台分发才安全。代价是 AVX2 与通用代码不能跨 TU 内联，但对吞吐量型内核可忽略。

## 7. Benchmark：可复现的观测，不设硬门禁

`benchmarks/` 提供两个程序（**不进入 ctest 门禁**，仅记录）：

- `operator_benchmark`：单算子多版本对拍，输出 CSV（耗时、GiB/s、相对 naive 加速比）。
- `image_pipeline_benchmark`：完整预处理链路 `Resize → Normalize → WarpAffine → Crop → Transpose`，跨后端逐 stage 比较。

**解读纪律**（写进 PLAN §10，避免误读）：

1. **加速比只在同一构建树内可比**：naive 是 `long double` 参考实现，对编译器敏感（同一源码 g++ -O3 与 clang++ -O3 耗时可差数倍），跨构建树的绝对耗时不可直接比。
2. **OpenCV/CUDA 计时抖动可达 ±30%**，趋势判断以多次运行中位数为准。
3. **不静默降级**：无法跑完整链路的后端/level 打印 `# skip <backend>/<level>: <原因>`，而不是偷偷换实现。
4. **缓存复用靠验证而非假设**：CPU 分配器按精确字节缓存空闲块，基准用"连续两轮缓冲区地址完全相同"验证 `cache_reuse=yes`。

本机实测示例（Release）：Add AVX2 相对 naive 加速约 23×；图像处理链路 CUDA 相对 native naive 约 134×、OpenCV 约 33×。完整数据见 [`PLAN.md`](../../PLAN.md) §10。

## 8. 新增一个 CPU 优化版本的步骤

以给 `Add` 加 `kSimdNeon` 为例：

1. 新建 `src/ops/add/add_cpu_neon.cpp`，实现 `Status AddCpuNeon(const OpContext&, const Tensor&, const Tensor*, const void*, Tensor*)`，遵守 bit-exact 约定。
2. 在 `src/ops/add/add.cpp` 前置声明并在 `RegisterAddKernels()` 里加：
   ```cpp
   #ifdef MYCV_ARCH_NEON
   RegisterKernel(OpKind::kAdd, BackendType::kNativeCpu,
                  CpuKernelLevel::kSimdNeon, &AddCpuNeon);
   #endif
   ```
3. 在 CMake 中为该 TU 单独加 NEON 编译选项（`-mfpu=neon` 等，按目标平台）。
4. 在 `tests/consistency/test_cpu_kernels.cpp` 增加 naive vs NEON 的 bit-exact 对拍。
5. 约束：**不改 naive 与已有版本**；未满足 bit-exact 必须先说明误差来源并按容差约定处理。

## 9. 验收

- 元素级算子多版本 bit-exact；插值类误差在约定容差内。
- 请求未编译的 level 返回 `kUnsupported`，绝不静默换实现。
- `benchmarks/operator_benchmark` 可实际运行并输出 CSV。
- 三棵构建树（`build` / `build-default` / `build-asan`）ctest 全绿。
