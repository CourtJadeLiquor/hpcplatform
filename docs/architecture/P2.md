## 1. 范围

P2 做两件事：

1. 建立一套**与具体算子解耦的分发框架**：给定"哪个算子 + 哪个后端 + 哪个 CPU 级别"，精确返回一个内核函数，查不到就返回确定的错误码——绝不静默换实现。
2. 提供 8 个算子的 **naive 参考实现**，作为后续优化版本与跨后端对拍的 ground truth。

本文讲分发框架；算子矩阵与各后端实现见 [`P3.md`](./P3.md)–[`P5.md`](./P5.md)。

## 2. 调用方看到的算子 API

每个算子在 `include/mycv/ops/<op>.h` 暴露一个稳定的函数式入口。以 `Add` 为例（[add.h](../../include/mycv/ops/add.h#L11-L12)）：

```cpp
Result<Tensor> Add(const OpContext& context, const Tensor& input,
                   const Tensor& other);
```

`OpContext`（[op.h](../../include/mycv/ops/op.h#L13-L17)）是**单次调用**的调度描述符：

```cpp
struct OpContext {
  Context* context = nullptr;
  Stream* stream = nullptr;        // nullptr -> 用 Context 的默认流
  CpuKernelLevel cpu_level = CpuKernelLevel::kNaive;
};
```

`OpKind`（[op.h](../../include/mycv/ops/op.h#L20-L29)）是算子的稳定 id：`kAdd=1 … kWarpAffine=8`。**新增算子只追加、永不重排**——id 一旦发布就固化，避免持久化/序列化场景错位。

## 3. 一次 Add 调用的完整链路

以 `Add` 为例（[add.cpp](../../src/ops/add/add.cpp#L46-L58)），算子公共函数的结构是固定的：

```
Add(ctx, input, other)
  │
  ├─ 1. ValidateInvocation(ctx, input)         // 设备/后端匹配
  ├─ 2. ValidateBinaryInputs(input, &other)    // shape/dtype/广播校验
  ├─ 3. FindKernel(kAdd, input.backend(), ctx.cpu_level)
  │        └─ 命中 → OpKernelFn；未命中 → Status（见 §5）
  ├─ 4. AllocateOutput(ctx, input.shape(), dtype)   // 在 ctx 后端上分配输出
  └─ 5. kernel(ctx, input, &other, nullptr, &output)   // 执行
```

这套"校验 → 查表 → 分配 → 执行"的骨架对所有算子一致，差异只在参数校验与内核签名。内核的统一签名（[op_registry.h](../../src/ops/op_registry.h#L15-L17)）：

```cpp
using OpKernelFn = Status (*)(const OpContext&, const Tensor& input,
                              const Tensor* other, const void* params,
                              Tensor* output);
```

- `other`：二元算子的第二操作数（一元算子传 `nullptr`）；
- `params`：算子的不可变参数结构体（如 `Resize` 的插值方式、`Normalize` 的均值方差），在同步调用期间有效；
- `output`：已由第 4 步分配好的输出张量，内核只负责写入。

## 4. 分发表：三元组 → 函数指针

### 4.1 键

注册与查询的键是三元组（[op_registry.cpp](../../src/ops/op_registry.cpp#L28)）：

```
(OpKind, BackendType, CpuKernelLevel)  →  OpKernelFn
```

用 `std::map<std::tuple<int,int,int>, OpKernelFn>` 存储。之所以用三元组而不是"op 里塞个 switch"，是为了让**后端与 CPU 级别的增减完全正交**：加一个 CUDA 后端不需要改任何 CPU 算子文件，加一个 AVX2 版本不需要改其他后端。

### 4.2 注册时机：延迟、一次性

注册通过 `std::call_once` 延迟完成（[op_registry.cpp](../../src/ops/op_registry.cpp#L35-L54)）：第一次 `FindKernel` 时，依次调用 `RegisterAddKernels()` …… `RegisterWarpAffineKernels()`，以及按编译宏条件注册的 `RegisterOpenCvKernels()` / `RegisterCudaKernels()`。

每个算子的注册函数用 `#ifdef` 守卫（[add.cpp](../../src/ops/add/add.cpp#L23-L42)）：

```cpp
void RegisterAddKernels() {
  RegisterKernel(kAdd, kNativeCpu, kNaive, &AddCpuNaive);
#ifdef MYCV_WITH_OPENMP
  RegisterKernel(kAdd, kNativeCpu, kOpenMP, &AddCpuOpenMP);
#endif
#ifdef MYCV_ARCH_AVX2
  RegisterKernel(kAdd, kNativeCpu, kSimdAvx2, &AddCpuAvx2);
#endif
  // ...
}
```

> 含义：**编译期没开的能力，运行期根本不会出现在表里**。请求它就得到明确错误，而不是"有条件地可用"。这是"不静默降级"在编译期的保证。

## 5. 错误语义：三种"不能跑"的精确区分

`FindKernel`（[op_registry.cpp](../../src/ops/op_registry.cpp#L64-L86)）对未命中的情况给出**不同的 `StatusCode`**，这是调用方判定行为的依据，必须准确理解：

| 场景 | StatusCode | 含义 | 例 |
| --- | --- | --- | --- |
| 非 CPU 后端请求了非 `kNaive` 级别 | `kInvalidArgument` | 参数非法：该后端根本没有"多版本"语义 | OpenCV 传 `kOpenMP` |
| CPU 后端请求了**未编译**的级别 | `kUnsupported` | 这个 CPU level 没被构建进当前二进制 | 未开 `-mavx2` 时请求 `kSimdAvx2` |
| 后端**未实现**该算子 | `kNotImplemented` | 这个后端压根没注册这个 op | NPU 后端的任意算子 |

口诀：

- **参数错**（后端不接受这个 level）→ `kInvalidArgument`
- **能力没编译进来**（CPU level 未注册）→ `kUnsupported`
- **功能没实现**（后端无此 op）→ `kNotImplemented`

> 为什么要分这么细：调用方需要据此决定"是我传参错了"、"换个构建开关"、还是"这个后端就是不支持"。混为一谈会让上层无法写正确的降级逻辑（注意：降级逻辑在**调用方**，库本身不做）。

## 6. 校验层

算子公共函数在查表前调用 `ops_internal` 的统一校验 helper（位于 `src/ops/op_common.h`），典型包括：

- `ValidateInvocation(context, input)`：`input` 的 `backend()` 与 `context` 的后端一致、设备匹配；这也是为什么 `Wrap` 出来的张量能直接当输入——它的 `backend()`/`device()` 与上下文匹配（见 [`P1.md`](./P1.md) §11）。
- `ValidateBinaryInputs`：二元算子的 shape 匹配或标量广播、dtype 一致。
- `AllocateOutput`：在 `context` 的后端上分配输出，分配失败返回 `kOutOfMemory`。

校验失败直接返回错误，**不会走到查表与执行**。

## 7. 新增一个算子的步骤

假设新增算子 `Foo`：

1. **追加 `OpKind`**：在 `include/mycv/ops/op.h` 的 `OpKind` 末尾加 `kFoo = 9`（只追加，不重排），并在 `OpKindName` 加对应分支。
2. **声明公共入口**：新建 `include/mycv/ops/foo.h`，写 `Result<Tensor> Foo(const OpContext&, const Tensor&, ...)`；在伞形头 `include/mycv/mycv.h` 包含它。
3. **实现分发与内核**：新建 `src/ops/foo/foo.cpp`（校验 + `FindKernel` + 分配 + 执行 + `RegisterFooKernels`）和 `foo_cpu_naive.cpp`（ground truth）。
4. **接入注册**：在 `src/ops/op_registry.cpp` 的 `EnsureRegistered` 里加 `RegisterFooKernels();`，并前置声明。
5. **补其他版本/后端**（可选）：按 `#ifdef` 加 `foo_cpu_omp.cpp` 等，或在 OpenCV/CUDA 后端注册。
6. **测试**：在 `tests/unit/` 加手算小例 + 边界（单元素、非连续、不支持 dtype）；在 `tests/consistency/` 加多版本/跨后端对拍。

> 约束：**不改已有算子、不改 core、不改其他后端**。新增是纯追加。

## 8. 测试与容差

测试分三层（详见 [`P0.md`](./P0.md) §8 与仓库根 [`PLAN.md`](../../PLAN.md) §6）：

| 层次 | 位置 | 门禁 |
| --- | --- | --- |
| 单元测试 | `tests/unit/` | ctest 必过 |
| 一致性对拍 | `tests/consistency/` | ctest 必过 |
| 内存检查 | `build-asan/`（ASAN/UBSAN） | 必过 |

**容差约定**（P2 起固定）：

- 整数类型：bit-exact；
- 元素级浮点：同 level 内 bit-exact，跨实现 1e-6 相对；
- 插值类（Resize/WarpAffine）：1e-5 相对，u8 输出允许 ±1；
- 跨后端：1e-4 相对。

P2 退出条件：8 个算子在 `kNaive` 下全部通过，未实现组合返回正确错误码且信息含 op 名与 level，`-Wall -Wextra -Wpedantic` 零警告。
