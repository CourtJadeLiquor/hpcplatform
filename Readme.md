# 背景
需要将算法涉及到的算子和工具整合到一个库中，内部实现的算法中包含opencv及contrib库中的算子，matlab转译来的算子，以及cuda实现的算子，大部分是跑在cpu上。当初的想法是参考opencv开发一个uscv库，复用opencv的数据结构，用于整合超声图像分析领域的相关算法和工具。但是这个目标太大了，远远超出了当前项目的现状，毕竟眼前的任务是逐步替换算法中的算子为uscv库中的同一版本。后来又接到了一个更急的需求，需要迁移团队所有自研、第三方算法到app中单独运行，而不是每个算法以动态库的形式集成到软件或者服务中。当时内部有几套推理框架，几个功能模块都不一致，另外部署链路也是完全不同的，历史包袱太重，想要一个个迁移实在是太麻烦几乎不可能，随考虑做一个算法开发部署包，让每个开发适配一下接口。主要目的就是统一算法开发部署流程，统一接口，将项目正规化，每个算法只需要适配一层输入输出转换。当时做了个算法平台，每个算法作为单独插件运行在平台上，新算法只需要参考SDK提供的几个模板类实现（例如2D、3D、传统算法等），运行时统一管理调度资源并完成模型推理工作，开发者只需要同时配置好模型参数和算法需要的业务参数，不用关心推理细节，在算法实现时主要关注链路逻辑的实现并在需要的时候调用推理pipline接口即可。这里统一了模型推理接口，但是后处理算法涉及到大量的算子，也需要同步规范化，本项目就是要解决这个问题，让你从高贵的C++软件算法工程师退化为掉包侠，让初级工程师都能很快上手。

当时做了一个0.1.0版本，收集了一些常用算子，并基于opencv的抽象类，实现了基本的算子接口和一些滤波算法。 例如 ```void exec(const cv::inputarray& input, const AlgoParams& params, cv::outputarray& output)```;也做了cuda opencl的兼容，仿照opencv的parallerBody接口，实现了在cpu上的并行计算，并留下了cuda opencl上的实现路径，但是当时的一个demo实现并没有发现cuda或者opencl有性能上的提升，加上进度原因，就没有继续投入。现在离职了歇一会，再面试半导体缺陷检测算法时，了解到他们需要招一个有cuda算子实现经验的人，满足实时性算法，而且它们是自研的算法库，不是基于opencv的，随仔细思考了一下这方面的实现，绑定到opencv确实太局限了，虽然它的封装思想也很有借鉴意义，但是无疑又给项目套上了枷锁，还涉及到开源协议等问题。于是便有了这个项目，让大模型教会我如何实现cuda等跨平台的算子，它主要作为一个学习研究项目，研究如何进行算子开发，如何使用cuda加速，如何串联多个kernel，复用输入输出缓存，减少数据拷贝，达到算法优化的目的。


# 需求
创建一个高性能算子研究平台
- 支持python和c++接口
- 支持cpu多线程并行计算
- 支持gpu加速
- 支持跨平台部署
- 提供完备的学习路径和测试用例

# 设计
   当然先要搭一个基础框架，定义契约，统一设计理念，方便后续针对算子的开发。
- 内部核心数据结构，错误处理机制必须显示手动处理，参考rust
- 接口隔离、core层只提供基本的算子接口，不提供实现细节
- 业务层根据需要实现具体的算子，调用core层的接口
