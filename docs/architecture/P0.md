## 1. 文档定位

本文是 mycv 的**架构宪法**。它不逐行解释实现，而是回答四个问题：

1. 这个库**解决什么问题、不解决什么问题**？
2. 它由**哪些层、哪些核心抽象**组成？
3. 每一个重大设计决策**为什么这么选**，代价是什么？
4. 未来扩展时**哪些边界不能碰**？

各里程碑的细节（Tensor 内存模型、算子分发、CPU 优化、OpenCV/CUDA 后端）在 `P1.md`–`P5.md` 中展开；本文是它们的上位约束。

## 2. 项目定位

mycv 是一个**跨平台 C++17 算子库**，服务于科研平台的图像/张量预处理。同一套 API 可以调度：

- 原生 CPU 内核（含 naive / OpenMP / TBB / SIMD / AVX2 多版本）；
- OpenCV 后端；
- CUDA 后端；
- 未来的 NPU 后端。

它的定位是**算子层**，不是深度学习框架：不做图编译、自动微分、算子融合、自动调度。调用方**显式**选择在哪个后端、以哪个 CPU 级别运行，库保证"你选什么就跑什么"。

### 2.1 目标

| # | 目标 | 落地位置 |
| --- | --- | --- |
| G1 | 一套 core 抽象屏蔽 CPU / OpenCV / CUDA / NPU 差异 | `include/mycv/core/` |
| G2 | 后端可替换，OpenCV/CUDA 只是 `BackendType` 之一，非依赖本体 | `include/mycv/backends/backend.h` |
| G3 | 对上只暴露 `MemoryManager`，向下各后端自实现分配 | `include/mycv/core/memory.h` |
| G4 | 同一算子提供多 CPU 实现，由 `CpuKernelLevel` 显式选择 | `include/mycv/core/kernel_level.h` |
| G5 | 编译期开关、运行期显式指定，不做平台探测与自动降级 | `Context::Create` + CMake `option()` |
| G6 | 工程完备：CMake、单元/一致性测试、samples、benchmark | 仓库根目录 |

### 2.2 明确不做（MVP 边界）

| 不做 | 原因 |
| --- | --- |
| 自动平台/后端识别 | 与科研核心诉求无关，行为不可预期 |
| 运行时自动降级（CUDA 失败回退 CPU 等） | 实验结论不可复现 |
| 算子融合、图编译、自动微分 | 属于更高层框架 |
| 复刻 OpenCV 全量 API | OpenCV 只是后端之一 |
| Python 绑定（现阶段） | 留到 P6 以稳定 C ABI 补齐 |
| 分布式 / 多机 | 超出库的职责 |

## 3. 核心设计哲学

这五条原则是所有后续决策的依据。任何新设计若与它们冲突，必须先修改本文档。

### 3.1 显式优于隐式

后端由 `Context::Create(BackendType, device_index)` 显式命名（[context.h](../../include/mycv/core/context.h#L21-L22)）；CPU 实现版本由 `OpContext.cpu_level` 显式指定（[op.h](../../include/mycv/ops/op.h#L13-L17)）。**不存在"运行时发现 CUDA 不可用就回退 CPU"的路径。**

> 动机：科研实验要求可复现。"以为在跑 AVX2，其实跑的是 naive"或"GPU 不可用就悄悄用 CPU"会让性能数字和结论失真。显式选择让每一次实验的执行路径都可被代码审计。

### 3.2 可复现优于方便

请求一个未编译的 CPU 级别返回 `kUnsupported`；非 CPU 后端传入非 `kNaive` 返回 `kInvalidArgument`；后端未实现某算子返回 `kNotImplemented`（[op_registry.cpp](../../src/ops/op_registry.cpp#L64-L86)）。**错误码即契约**，调用方据此判定，而不是依赖隐式行为。

### 3.3 描述符与存储分离

`Tensor` 只是一个描述符：`shape + dtype + strides + offset + shared_ptr<Buffer>`（[tensor.h](../../include/mycv/core/tensor.h#L91-L101)）。真正的内存由 `Buffer` 持有，而"如何释放"由后端注入的 `Buffer::Deleter` 决定（[memory.h](../../include/mycv/core/memory.h#L32-L43)）。

> 动机：让 `View` / `Slice` / `Permute` 成为零拷贝的元数据操作；让同一块内存可以被 `posix_memalign`、`cv::Mat`、`cudaMalloc`、NPU DMA 池等不同来源填充，而 `Tensor` 对此一无所知。

### 3.4 后端可替换，core 零第三方依赖

core 层（`include/mycv/core/` 与 `src/core/`）**不允许 `#include` 任何第三方头**。OpenCV / CUDA / 厂商 SDK 只能出现在 `src/backends/<name>/`。新增后端 = 新增目录 + 在 `backend_factory.cpp` 加一个 `case`，**不改 core**。

> 动机：保持核心抽象的可移植性与可测试性；第三方依赖的有无不影响核心类型的编译与单测。

### 3.5 错误不抛异常，`-fno-exceptions` 可用

错误通过 `Status` / `Result<T>` 传播（[error.h](../../include/mycv/core/error.h)），core 不 `throw`。

> 动机：部分 NPU / 嵌入式工具链以 `-fno-exceptions` 编译；异常也会让 C ABI 边界与跨语言绑定变复杂。

## 4. 分层架构

```
┌───────────────────────────────────────────────────────────────┐
│  应用层                                                        │
│  auto ctx = Context::Create(BackendType::kCUDA).value();       │
│  auto out = Add(OpContext{ctx.get()}, a, b);                   │
└───────────────────────────┬───────────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────────┐
│  算子层  include/mycv/ops/*.h                                   │
│  稳定函数式入口：Result<Tensor> Add(OpContext, Tensor, Tensor)  │
│  负责：参数校验 → 查分发表 → 分配输出 → 调用内核                  │
└───────────────────────────┬───────────────────────────────────┘
                            │  (OpKind, BackendType, CpuKernelLevel)
┌───────────────────────────▼───────────────────────────────────┐
│  分发层  src/ops/op_registry.{h,cpp}                            │
│  全局三元组 → 函数指针表；std::call_once 延迟注册                 │
└───────────────────────────┬───────────────────────────────────┘
                            │  OpKernelFn
┌───────────────────────────▼───────────────────────────────────┐
│  内核层  src/ops/<op>/*_<level>.cpp  +  src/backends/<name>/    │
│  CPU: naive / openmp / tbb / simd / avx2                        │
│  后端: opencv_kernels.cpp / cuda_kernels.cu                     │
└───────────────────────────┬───────────────────────────────────┘
                            │ 读/写 Tensor
┌───────────────────────────▼───────────────────────────────────┐
│  核心抽象 Core  include/mycv/core/                              │
│  Tensor · Buffer · MemoryManager · Stream · Context ·           │
│  Shape · Device · DataType · Status/Result                      │
└───────────────────────────┬───────────────────────────────────┘
                            │ 虚接口 Backend
┌───────────────────────────▼───────────────────────────────────┐
│  后端层  src/backends/<name>/                                   │
│  native_cpu │ opencv │ cuda │ npu(占位)                         │
│  各自实现 MemoryManager / Stream / CopyBuffer / 内核注册         │
└───────────────────────────────────────────────────────────────┘
```

**关键不变量**：

- 调用方**永远不直接**接触后端实现类，只通过 `Context` 与算子函数交互。
- 算子层与后端层之间只通过 `Tensor`（数据）和 `OpContext`（调度）解耦。
- 所有跨层调用都返回 `Status` 或 `Result<T>`，没有异常逃逸。

## 5. 核心抽象一览

| 抽象 | 职责 | 关键文件 | 核心字段/方法 |
| --- | --- | --- | --- |
| `Tensor` | 描述符：shape/dtype/strides/offset + 共享 Buffer | [tensor.h](../../include/mycv/core/tensor.h) | `buffer_` / `owner_` / `shape_` / `strides_` / `offset_` |
| `Buffer` | 不透明内存句柄 + deleter | [memory.h](../../include/mycv/core/memory.h) | `data_` / `bytes_` / `kind_` / `deleter_` |
| `MemoryManager` | 统一分配/拷贝/统计接口（虚） | [memory.h](../../include/mycv/core/memory.h) | `Allocate` / `Copy` / `Stats` |
| `Stream` | 执行流抽象（虚） | [stream.h](../../include/mycv/core/stream.h) | `Synchronize` / `synchronous` |
| `Context` | 绑定一个 Backend + 一个 Device 的统一入口 | [context.h](../../include/mycv/core/context.h) | `Create` / `AllocateTensor` / `Wrap` / `Copy` |
| `Backend` | 后端虚接口：持有 memory/stream/私有状态 | [backend.h](../../include/mycv/backends/backend.h) | `memory` / `stream` / `CopyBuffer` / `SupportsKernelLevel` |
| `Shape` | 固定容量形状，无堆分配 | [shape.h](../../include/mycv/core/shape.h) | `dims_` / `kMaxDims` |
| `Device` / `BackendType` | 硬件与实现提供者分离 | [device.h](../../include/mycv/core/device.h) | `DeviceType` / `BackendType` / `DefaultDeviceType` |
| `DataType` | 元素类型 | [dtype.h](../../include/mycv/core/dtype.h) | `kUInt8`…`kInt64` / `DTypeSize` |
| `Status` / `Result<T>` | 无异常错误模型 | [error.h](../../include/mycv/core/error.h) | `StatusCode` / `MYCV_RETURN_IF_ERROR` |
| `OpContext` / `OpKind` | 调度描述符 + 稳定算子 id | [op.h](../../include/mycv/ops/op.h) | `context` / `stream` / `cpu_level` |
| `CpuKernelLevel` | CPU 实现版本枚举 | [kernel_level.h](../../include/mycv/core/kernel_level.h) | `kNaive`…`kTbb` |

## 6. 关键设计决策

| # | 决策 | 选择 | 理由 |
| --- | --- | --- | --- |
| D1 | 后端如何选择 | `Context::Create(BackendType, device_index)` 显式指定，失败返回 `kUnsupported` | 无隐式回退，实验可复现 |
| D2 | Backend 与 Device 的关系 | 两者分离：`BackendType` 是实现提供者，`DeviceType` 是硬件；`DefaultDeviceType()` 只做静态映射 | OpenCV 是 CPU 上的后端、CUDA 是 GPU 后端，混为一谈会让调度写死 |
| D3 | Tensor 的内存模型 | 描述符（shape/dtype/strides/offset）+ `shared_ptr<Buffer>` | 零拷贝 View/Slice/Permute；非连续 Reshape 显式深拷贝 |
| D4 | 内存释放 | `Buffer` 持有后端注入的 deleter；统计放在后端内部 shared state | Tensor 可比 Context 长寿，且便于接内存池 |
| D5 | 错误处理 | `Status` + `Result<T>`，core 不抛异常 | 兼容 `-fno-exceptions` 的 NPU/嵌入式工具链 |
| D6 | 多版本算子选择 | `OpContext.cpu_level` 显式指定；非 CPU 后端只接受 `kNaive` | 避免"以为在跑 AVX2，其实跑 naive" |
| D7 | 编译策略 | 静态库；x86 AVX2 内核独立编译单元单独加 `-mavx2`；不默认 `-march=native` | 跨平台分发不会因指令集导致非法指令 |
| D8 | 对齐 | 默认 64 字节，接口可传 | 兼顾 AVX-512（64B）与 cache line |
| D9 | 测试框架 | 零依赖 mini harness，注册式 | 科研环境常离线；后续可无痛换 gtest |

## 7. 扩展契约（Code Review Checklist）

这是新增代码必须遵守的硬边界，写进评审清单：

1. **新增后端** = 新增 `src/backends/<name>/` + 在 `backend_factory.cpp` 加一个 `case`，**不改 core**。
2. **新增算子** = 新增 `include/mycv/ops/<op>.h` + `src/ops/<op>/` + 在 `OpKind` **追加** id（永不重排），不改已有算子。
3. **新增 CPU 优化版本** = 新增一个 `*_<level>.cpp` + 在该算子的 `Register*Kernels()` 里加一行 `#ifdef`，不改 naive 实现。
4. **core 层不允许 `#include` 任何第三方头**（OpenCV/CUDA/厂商 SDK 只能在对应 backend 目录）。
5. **不静默降级**：任何"请求的实现不可用"场景必须返回确定的错误码，不得换实现重试。
6. **公开算子调用在返回前同步**（当前契约，见 `P5.md`）；若未来引入异步，必须另行定义输出生命周期与同步契约，不得隐式切换。

## 9. 设计的代价与已知局限

架构不是免费的。明确记录代价，避免未来误判为 bug：

| 取舍 | 换来的好处 | 代价 |
| --- | --- | --- |
| 显式选择、不自动降级 | 实验可复现、行为可审计 | 调用方需自行处理能力探测与降级（库不代劳） |
| 描述符与存储分离 | 零拷贝视图、跨后端统一 | `Slice`/`Permute` 视图会让整块底层内存存活，无法只释放片段 |
| deleter + shared state | Tensor 可长于 Context、可接内存池 | 比裸 RAII 多一层；池无上限、只精确匹配（见 [`P1.md`](./P1.md)） |
| core 零第三方依赖 | 可移植、单测不依赖 GPU/OpenCV | 第三方能力只能在后端目录表达 |
| 公开算子同步返回 | 生命周期简单、结果立即可读 | 无法重叠多算子；异步是未来可选扩展（非隐式） |
